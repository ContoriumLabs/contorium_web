Contorium

Git for AI Collaboration

Make AI tools share the same project memory — across IDEs, CLI, and agents.

Switch between Cursor, Claude Code, Gemini CLI, VS Code, Codex, or any MCP-compatible tool
without losing project context.

⸻

The Problem

AI coding tools are powerful — but disconnected.

Every time you switch:

* Cursor → Claude Code
* Claude Code → Gemini CLI
* IDE → Terminal → Another agent

The model forgets your project.

You rebuild context again and again.

Context fragmentation is the real bottleneck of AI development.

⸻

The Solution

Contorium introduces a shared workspace state layer inside your repository.

Instead of relying on chat history or prompt injection, Contorium maintains a persistent, structured project memory that all AI tools can read and update.

Not chat memory.
Not prompt stuffing.
Not orchestration.

A Git-like state layer for AI collaboration.

⸻

How It Works

        Workspace (Source of Truth)
                   │
                   ▼
        .contora/ State Layer
                   │
   ┌───────────────┼───────────────┐
   ▼               ▼               ▼
 IDE Extension   MCP Server       CLI
   │               │               │
Cursor / VSCode  Claude / Gemini   Terminal / CI

All tools interact with the same persistent project state.

⸻

Core Idea

Instead of passing long prompts or relying on memory windows, Contorium tracks:

* Project goal
* Active modules
* Open problems
* Recent changes
* Next actions

Every AI agent sees the same structured reality.

Quick Start

IDE (VS Code / Cursor)

npm install
npm run compile
npm run vsix

Install the generated VSIX and open a workspace.

Run:

Contorium: Copy AI-ready context

⸻

MCP Server

npm install
npm run compile

Set workspace:

CONTORIUM_WORKSPACE=/your/project/path

Available tools:

* get_project_snapshot
* get_workspace_context
* get_project_state

⸻

CLI

npx contorium init .
npx contorium snapshot .
npx contorium state .
